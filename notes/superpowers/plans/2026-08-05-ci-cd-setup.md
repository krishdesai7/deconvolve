# CI/CD Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give RANv4 an enforced GitHub Actions CI gate with inline PR annotations, local pre-commit hooks, and a full release pipeline (version bump → tag → PyPI + GitHub Release).

**Architecture:** A `.github/workflows/ci.yml` job runs on every PR and push to `master`/`refactor/jax`, using dedicated actions (`ruff-action`, pyrefly's action, `complexipy-action`) for inline-annotated lint/format/type/complexity checks, plus `just test`/`just audit` for the rest. A `.pre-commit-config.yaml` mirrors the fast subset of that locally. Three release workflows (`prepare-release.yml`, `tag-release.yml`, `release.yml`) chain together: manual dispatch bumps the version and opens a PR via `rooster`, merging that PR auto-tags, and the tag push builds + publishes to PyPI + creates a GitHub Release.

**Tech Stack:** GitHub Actions, `uv`, `just`, `pre-commit`, `ruff`, `pyrefly`, `complexipy`, `rooster`, PyPI Trusted Publishing.

## Global Constraints

- Pin `actions/checkout` to `v7` and `astral-sh/setup-uv` to commit `c771a70e6277c0a99b617c7a806ffedaca235ff9` (tagged `v9.0.0`) everywhere they're used — older releases of both trigger Node-version-deprecation warnings on every run.
- Python version is `3.13` (from `requires-python` in `pyproject.toml`); no matrix, single `ubuntu-latest` runner.
- `just check`/`just ci` in the `Justfile` are unchanged and remain the correct way to run everything locally — CI composes checks differently (dedicated actions for lint/format/type/complexity) but doesn't replace them.
- No SHA-pinning beyond `checkout`/`setup-uv`; other third-party actions are referenced by tag (`ruff-action@v4.1.0`, `complexipy-action@v6.2.0`) or, where upstream only publishes that way, by branch (`facebook/pyrefly@main`).
- Repo is public on GitHub as `krishdesai7/RANv4`; package name on PyPI is `ran` (not yet published).
- For Tasks 1-2 (in scope now): base branch is `refactor/jax`, not `master` — see Execution Status above.
- Full design rationale lives in `docs/superpowers/specs/2026-08-05-ci-cd-setup-design.md` — consult it for the "why" behind any of the above.

```yaml
      - name: Complexity check
```

### Task 4: `prepare-release.yml`

**Files:**
- Create: `.github/workflows/prepare-release.yml`

**Interfaces:**
- Consumes: `rooster` (the `release` dependency group in `pyproject.toml`, already present — no change needed).
- Produces: a `release/X.Y.Z` branch and PR against `master`, consumed by Task 5 (`tag-release.yml`).

- [ ] **Step 1: Create `.github/workflows/prepare-release.yml`**

```yaml
name: Prepare release

on:
  workflow_dispatch:
    inputs:
      bump:
        description: "Version bump (leave blank to infer from merged PR labels)"
        type: choice
        options: [major, minor, patch, pre]
        required: false

permissions:
  contents: write
  pull-requests: write

jobs:
  prepare:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0

      - name: Install uv
        uses: astral-sh/setup-uv@c771a70e6277c0a99b617c7a806ffedaca235ff9 # v9.0.0

      - name: Install dependencies
        run: uv sync --group release --frozen

      - name: Bump version and update changelog
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          BUMP: ${{ inputs.bump }}
        run: |
          if [ -n "$BUMP" ]; then
            uv run rooster release --bump "$BUMP"
          else
            uv run rooster release
          fi

      - name: Read new version
        id: version
        run: |
          version=$(grep -m1 '^version = ' pyproject.toml | sed -E 's/version = "(.*)"/\1/')
          echo "version=$version" >> "$GITHUB_OUTPUT"

      - name: Open release PR
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git checkout -b "release/${{ steps.version.outputs.version }}"
          git add pyproject.toml CHANGELOG.md
          git commit -m "Release ${{ steps.version.outputs.version }}"
          git push -u origin "release/${{ steps.version.outputs.version }}"
          gh pr create \
            --title "Release ${{ steps.version.outputs.version }}" \
            --body "Automated version bump and changelog update via rooster." \
            --base master \
            --head "release/${{ steps.version.outputs.version }}"
```

Note: `rooster release` creates `CHANGELOG.md` on its first run if it doesn't already exist (this repo has none yet) — the `git add pyproject.toml CHANGELOG.md` step is correct either way.

- [ ] **Step 2: Validate the YAML parses**

```bash

```

Expected: no output, exit code 0.

### Task 5: `tag-release.yml`

**Files:**
- Create: `.github/workflows/tag-release.yml`

**Interfaces:**
- Consumes: a merged PR from a `release/*` branch (produced by Task 4's workflow).
- Produces: a pushed git tag matching `X.Y.Z`, consumed by Task 6 (`release.yml`)'s trigger.

- [ ] **Step 1: Create `.github/workflows/tag-release.yml`**

```yaml
name: Tag release

on:
  pull_request:
    types: [closed]

permissions:
  contents: write

jobs:
  tag:
    if: >-
      github.event.pull_request.merged == true &&
      startsWith(github.event.pull_request.head.ref, 'release/')
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          ref: master

      - name: Read version
        id: version
        run: |
          version=$(grep -m1 '^version = ' pyproject.toml | sed -E 's/version = "(.*)"/\1/')
          echo "version=$version" >> "$GITHUB_OUTPUT"

      - name: Tag and push
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git tag "${{ steps.version.outputs.version }}"
          git push origin "${{ steps.version.outputs.version }}"
```

- [ ] **Step 2: Validate the YAML parses**


Expected: no output, exit code 0.

### Task 6: `release.yml`

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: the tag pushed by Task 5's workflow.
- Produces: a published PyPI release and a GitHub Release. Nothing downstream in this repo consumes it.

- [ ] **Step 1: Create `.github/workflows/release.yml`**

```yaml
name: Release

on:
  push:
    tags: ["[0-9]+.[0-9]+.[0-9]+"]

permissions:
  contents: write
  id-token: write

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7

      - name: Install uv
        uses: astral-sh/setup-uv@c771a70e6277c0a99b617c7a806ffedaca235ff9 # v9.0.0

      - name: Install dependencies
        run: uv sync --frozen

      - name: Build
        run: uv build

      - name: Publish to PyPI
        run: uv publish

      - name: Create GitHub release
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: gh release create "${{ github.ref_name }}" dist/* --generate-notes
```
